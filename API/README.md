# API backend

The solution is split into four projects:

- `Domain`: user model, `BaseEntity`, and `Category : BaseEntity`.
- `Application`: authentication and category use cases, DTOs, repository and Unit of Work contracts.
- `Infrastructure`: password hashing, user repository, JWT issuance, EF Core SQLite persistence.
- `API`: HTTP endpoints, authentication middleware, and authorization policies.

## Run locally

From the repository root:

```powershell
dotnet restore API\API.sln
dotnet run --project API\API\API.csproj
```

Development JWT settings are in `API/API/appsettings.Development.json`. For non-development environments, provide `Jwt__Issuer`, `Jwt__Audience`, `Jwt__Secret` (at least 32 bytes), and optionally `Jwt__ExpirationMinutes` through environment variables or a secret store. Do not reuse the development secret in deployment.

The current in-memory repository has sample accounts `admin` and `user`, both with password `ChangeMe123!`. The admin has `weather.read` and `weather.manage`; the user has `weather.read`. This repository is only a runnable scaffold: replace it with persistent user/role/permission storage before deploying.

## Category and Unit of Work

Categories are persisted in SQLite, independently of the sample authentication repository. `ConnectionStrings:DefaultConnection` defaults to `Data Source=core.db`, resolved relative to the API content root. Override it with `ConnectionStrings__DefaultConnection` if needed. The initial database is created on startup with `EnsureCreatedAsync`; schema changes to an existing database require a migration strategy before deployment.

`BaseEntity` provides an integer `Id` generated by the database, `CreatedAtUtc`, and nullable `UpdatedAtUtc`. `Category` adds a required, trimmed `Name` (maximum 200 characters) and optional `Description` (maximum 2000 characters). Updating a category sets `UpdatedAtUtc`. Sample users also have integer IDs: admin is 1, user is 2; JWT subject and name identifier claims contain those IDs as strings.

`CategoryService` accepts `CreateCategoryDto` / `UpdateCategoryDto` and returns `CategoryDto` (or a collection for list queries). These DTOs live in `Application/Categories/DTOs`. Mapping is configured in `Application/Categories/Mappings/CategoryMappingConfig.cs` using Mapster and injected as `IMapper`. Create/update mappings call the domain constructor and `Update` method to preserve validation and timestamps; updates map onto the tracked entity without changing its ID or creation timestamp. Category routes use integer IDs, for example `/api/categories/1`. An existing database created with the previous GUID keys needs schema/data migration; `EnsureCreatedAsync` does not update it automatically.

`CategoryService` accesses `IUnitOfWork.Categories`. Repositories stage changes in the request-scoped `AppDbContext`; only `IUnitOfWork.SaveChangesAsync` commits them. A single save commits all staged database changes atomically. The DI container owns and disposes the context at the end of the request.

- `GET /api/categories?page=1&pageSize=20` and `GET /api/categories/{id}` require `categories.read`.
- `POST /api/categories`, `PUT /api/categories/{id}`, and `DELETE /api/categories/{id}` require `categories.manage`.
- POST/PUT body: `{ "name": "Electronics", "description": "Electronic products" }`.
- POST returns `201` with a Location header; PUT returns `200`; DELETE returns `204`; missing records return `404`; invalid input returns `400`.
- Page starts at 1 (maximum 1000000), pageSize is from 1 to 100. The sample admin has both category permissions; the sample user can only read categories. Obtain a new JWT after permission changes.

## Endpoints

- `POST /api/auth/login` — JSON body `{ "userName": "admin", "password": "ChangeMe123!" }`; returns a bearer token.
- `GET /api/auth/me` — requires a valid bearer token.
- `GET /api/weatherforecast` — requires `weather.read`.
- `POST /api/weatherforecast/manage` — requires `weather.manage`.

Pass the token as `Authorization: Bearer <token>`. Add policies in `API/Program.cs` and issue the matching `permission` claim from the user repository/token issuer as the application grows.
